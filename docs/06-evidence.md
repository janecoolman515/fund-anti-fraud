# 取证规范

> 报告的说服力，90% 来自证据质量。
>
> 一份证据表里如果有一张"看不清、不知从哪来、不知道什么时候截的"图，
> 整份报告的可信度都会被拖累。

---

## 一 · 证据的四个等级

按证明力从强到弱：

### 第 1 级 · 官方文书（最强）

| 类型 | 获取方式 | 为什么强 |
|---|---|---|
| 法院判决书 / 裁定书 | 中国裁判文书网 | 法庭已认定的事实，可直接引用 |
| 公安通报 / 立案告知书 | 官方公众号、办案机关 | 已进入刑事程序 |
| 监管处罚决定书 | 金融监管总局、地方金融局、市场监管 | 行政认定 |
| 工商登记信息 | 国家企业信用信息公示系统 | 官方数据库 |
| ICP 备案信息 | 工信部备案系统 | 官方数据库 |

**这一级不需要你论证，直接引用即可。** 但要注意：
引用判决时区分"被告"和"受害人"；引用处罚决定时看处罚**具体内容**，
不要只看"被罚过"。

### 第 2 级 · 项目方自己发布的内容（次强）

| 类型 | 为什么强 |
|---|---|
| APP 内的收益制度页 | **它自己写的**，无法否认 |
| 官方群公告 / 客服话术 | 同上 |
| 官网宣传页 | 同上 |
| 招商会现场照片/视频 | 同上 |
| 项目方公众号文章 | 同上 |

**这一级的特点是"自证"**——它不能说你造假，因为东西是它自己发的。

**取证要求**：必须能证明"这确实来自该项目"。
- 截图要包含 URL 或 APP 界面特征
- 最好录屏（从打开 APP 到翻到制度页的完整过程）

### 第 3 级 · 第三方公开数据

| 类型 | 注意 |
|---|---|
| 黑猫投诉 | 记录投诉数量、时间分布、内容摘要 |
| 媒体报道 | 记录媒体名称、发布时间、原文链接 |
| 社交平台讨论 | 只作辅助，不作主要证据 |
| 应用商店搜索结果 | 截"搜不到"的页面，注明搜索词与时间 |

### 第 4 级 · 当事人提供（最弱，但常常是唯一的）

| 类型 | 注意 |
|---|---|
| 转账记录 | 必须能看出收款方 |
| 微信聊天记录 | 必须完整，不能只截有利的部分 |
| 提现失败截图 | 记录时间与错误提示 |
| 合同/协议 | 全文，不要只截签名页 |

**这一级必须打码**（姓名、账号、手机号、身份证号），并在报告里注明
"由当事人提供，未经独立核实"。

## 二 · 截图规范

### 必须包含的信息

一张合格的证据截图，必须同时包含：

```
□ 内容本身（制度页/公告/聊天记录）
□ 时间信息（系统时间、消息时间戳）
□ 来源标识（URL 栏、APP 名称、群名称）
□ 账号主体（谁发的）
```

**缺任何一项，这张图就只能算"辅助材料"，不能进证据表主栏。**

### 反面例子

| 问题 | 为什么不行 |
|---|---|
| 只截了中间一段文字 | 无法证明来源和上下文 |
| 裁掉了顶部 URL 栏 | 无法证明是哪个网站 |
| 裁掉了消息时间 | 无法证明是什么时候说的 |
| 图片被压缩到看不清小字 | 关键数字（收益率）看不清 = 无效 |
| 打了很重的马赛克 | 把关键信息也挡住了 |

### 抓图的技术细节

**网页图片**：直接保存 `src` 拿到的往往是缩略图。
- 去掉 URL 里的 `tp=webp`
- 把 `wx_fmt=webp` 改成 `jpeg`
- 路径里的 `/640` 改成 `/0`（原图）

**长页面**：用整页截图，不要分屏拼接（拼接处容易断章取义）。

**APP 页面**：录屏优于截图。
录屏要包含：从桌面点击图标 → 进入 APP → 翻到目标页面 → 停留 3 秒。
这样能证明"这个页面确实在这个 APP 里"。

**动态内容**（如滚动的公告、限时倒计时）：录屏，并截图关键帧。

## 三 · 时间戳与元数据

### 为什么时间很重要

- 制度会改（今天截图，明天可能就改了）
- 域名会续费（"快到期"可能三个月后就续了）
- 工商会移出异常
- 投诉会增加

**所有时效性数据必须标注获取日期。** 这不是形式主义——
三个月后读者看到报告，需要知道这个信息还准不准。

### 怎么固定时间

| 方法 | 强度 | 说明 |
|---|---|---|
| 截图自带系统时间 | 中 | 可被修改，但结合其他证据可采信 |
| 文件名带日期 | 弱 | 仅作管理用 |
| 保存原始 HTML / JSON 响应 | 强 | 含服务器时间头 |
| 第三方时间戳服务 | 强 | 有法律效力，需付费 |
| 区块链存证 | 强 | 同上，成本更低 |

**个人审查够用的做法**：

```
证据目录/
  2026-10-20_备案查询_星辰国际.png
  2026-10-20_备案查询_星辰国际.html     ← 保存完整页面
  2026-10-21_工商登记_星辰国际.png
  2026-10-22_制度页_录屏.mp4
  2026-10-22_制度页_截图01.png
  _evidence.md                          ← 索引：每份证据的 URL、获取时间、说明
```

文件名统一 `YYYY-MM-DD_类型_项目名`，配合一个 `_evidence.md` 索引。

### `_evidence.md` 索引模板

```markdown
# 证据索引 · [项目名]

审查日期：2026-10-26

| 文件 | 类型 | 来源 URL | 获取时间 | 说明 |
|---|---|---|---|---|
| 2026-10-20_备案查询.png | 官方查询 | beian.miit.gov.cn | 2026-10-20 14:32 | 备案主体为个人 |
| 2026-10-22_制度页.mp4 | 项目方物料 | APP 内录屏 | 2026-10-22 09:15 | 日化1.8%，3级分销 |
```

## 四 · 隐私处理

### 必须打码的信息

```
□ 真实姓名（保留姓氏，如"张先生"）
□ 手机号（保留前3后2，如 138****23）
□ 身份证号（全部遮挡）
□ 银行卡号（保留后4位）
□ 微信/支付宝账号
□ 家庭住址
□ 人脸（除公开报道中的公众人物）
□ 车牌、门牌
```

### 打码的正确方式

| 方式 | 评价 |
|---|---|
| 黑色/灰色实心块覆盖 | ✅ 推荐 |
| 高斯模糊 | ⚠️ 可逆，弱隐私场景可用 |
| 马赛克（小方格） | ⚠️ 低分辨率下可能被还原 |
| 直接裁剪掉 | ✅ 安全，但可能丢失上下文 |
| 白色半透明覆盖 | ❌ 可能仍能看出轮廓 |

### 特殊情况

**项目方负责人**：如果是公开宣传中的形象（招商会演讲、宣传海报），
属于"已公开信息"，可以不放码，但要注明来源。

**"领导人"（团队长）**：即使他们在群里公开拉人，也建议打码。
理由：他们中的很多人本身也是受害者。

**受害者**：**一律打码，无例外。**

## 五 · 证据链完整性

单张截图证明力有限。**证据链 = 多份证据互相印证。**

### 一个完整的证据链长什么样

以"宣称国资背景但实际无股权关系"为例：

```
证据 1：宣传页截图 —— 上面写着"XX国资战略入股"
   ↓
证据 2：工商登记截图 —— 股东名单里没有该国资企业
   ↓
证据 3：该国资企业的声明（如有）—— "从未投资该公司"
   ↓
结论：宣称的背书不成立
```

**三份证据，缺一不可**：
- 只有证据 1 → 你在说它宣传了什么（不够）
- 只有证据 2 → 你在说它股东是谁（不够）
- 1 + 2 → 才能说"宣传与工商登记不符"

### 常见的不完整证据链

| 只有这个 | 缺什么 | 补什么 |
|---|---|---|
| "域名快到期"截图 | 到期时间与当前时间的关系 | 注明查询日期 |
| "提现失败"截图 | 这个页面是不是该项目的 | 录屏从 APP 首页进入 |
| "有人在群里说提现不到账" | 这个群是不是官方群 | 群名称 + 群主身份 |
| "工商经营异常" | 异常原因 | 截图异常原因栏 |

## 六 · 微信聊天记录的保存

聊天记录是最常见的证据，也是最容易被质疑的证据。要点：

### 保存方式

| 方式 | 强度 | 说明 |
|---|---|---|
| 手机截图 | 弱 | 可伪造，且容易断章取义 |
| 聊天记录迁移到电脑后截图 | 中 | 更完整 |
| **录屏**（从聊天列表进入 → 上滑到最早） | **强** | 能证明连续性 |
| 公证处公证 | 最强 | 有法律效力，成本较高 |

### 录屏要点

```
1. 从微信「聊天列表」开始录
2. 点进目标群/对话
3. 连续上滑，展示完整对话（不要跳段）
4. 点开对方头像，展示微信号
5. 停留 2 秒
```

### 注意

- **不要只截对自己有利的段落**。断章取义一旦被发现，整份证据作废。
- 保留原始载体（那台手机不要清理数据）。
- 如果是关键证据，考虑公证。

## 七 · 报告里的证据呈现

### 证据表格式

```markdown
| # | 核查项 | 查到的事实 | 说明什么 | 来源 | 获取日期 |
|---|---|---|---|---|---|
| 1 | ICP 备案主体 | 备案主体为个人（张*） | 宣称的集团背景无对应主体 | 工信部备案系统 | 2026-10-20 |
```

**关键**：「查到的事实」和「说明什么」**必须分栏**。
这是报告能被采信的技术前提——读者可以不同意你的推断，但不能绕过事实。

### 附件组织

```
REPORT.md              ← 报告正文
evidence/
  _index.md            ← 证据索引
  01_备案.png
  02_工商.png
  03_制度页.mp4
  04_投诉列表.png
```

报告正文里引用：`（见附件 03）`。

### 不要在报告里做的事

| ❌ 不要 | 为什么 |
|---|---|
| 放未打码的受害者信息 | 侵犯隐私，且可能被项目方反过来利用 |
| 放"内部人士"的私聊截图（未打码） | 可能让对方陷入危险 |
| 放抹掉水印的他人图片 | 删除权利管理信息，法律风险 |
| 用"据说""听说"作为证据 | 传闻不能作为事实 |
| 把截图裁到只剩一句话 | 断章取义 |

## 八 · 自检清单

交付前，逐条过：

```
□ 每份证据都能说清"从哪来、什么时候拿的"吗？
□ 关键截图能看清所有关键数字吗？（在手机上看一遍）
□ 隐私信息都打码了吗？（尤其是受害者）
□ 证据表里「事实」和「推断」分开了吗？
□ 有没有一条证据是"只有结论、没有过程"的？
□ 引用的链接现在还能打开吗？
□ 时效性数据标注日期了吗？
□ 如果对方要求你出示原始材料，你拿得出来吗？
```

最后一条最重要：**"你拿得出来吗"** —— 拿不出来，就别写进证据表。

---

*取证的目的不是"赢"，是"让人能自己判断"。*
